# Stage 5 — Tailwind, tests, and handoff

Stage 5 finishes the local demo with responsive/accessibility polish,
deterministic browser coverage, an opt-in live browser journey, a short
operator guide, and a sanitized real protocol trace. It does not change the
AG-UI/A2UI trust boundary.

## UI and accessibility

The shell now keeps `min-w-0`/`overflow-x-hidden` boundaries at every flex/grid
level, uses smaller mobile padding and minimum touch targets, and keeps the
inspector and A2UI surface usable at 375 px. Focus styles are explicit for
buttons, links, summaries, selects, and form controls; native labels remain the
accessible names used by the browser tests.

Verified by `tests/browser/fixture.spec.ts`:

- fixture form renders through the catalog renderer;
- empty review paints an in-surface validation/error summary in the same
  surface;
- keyboard focus + Enter triggers both the invalid and valid review actions;
- 375×812 has no horizontal document overflow before or after a form renders;
- Tab from **New request** reaches the first example button;
- **New request** clears the surface, prior review text, and returns to the
  empty examples state.

The fixture cleanup test intentionally uses **New request** because it is the
recovery path users need after a completed journey. The fixture protocol e2e
still covers `deleteSurface`/discard directly; run-level protocol coverage is
not weakened.

## Live verification

`npm run test:e2e:live` with the verified OpenRouter
`deepseek/deepseek-v4.1-flash-1017` configuration passed:

- four real model-composed surfaces (bug, feature, meeting, custom) with
  streaming text, `generate_a2ui`, catalog-validated activities, and distinct
  field compositions;
- full deterministic journey: invalid review → valid review → natural-language
  priority/justification update → stale review → re-review → edited submit →
  re-review → submit → double submit;
- public state stayed `editing/0 → review/1 → editing/2 → editing/2 (stale) →
  review/3 → editing/4 → review/5 → submitted-demo/6 → submitted-demo/6`;
- no `STATE_SNAPSHOT` exposed private checkpoint keys.

`npm run test:e2e:browser:live` passed 2/2 tests in 43.0s: all three examples
plus a custom request rendered forms; the review/update/re-review/submit/reset
journey passed through the real UI, including keyboard Enter on the focused
submit button. The suite remains opt-in and exits with
status 2 when credentials are missing.

## Protocol trace

`docs/protocol-trace.md` was generated by `tests/e2e/live.mjs` from the real
bridge SSE stream, not hand-written. It contains:

- the initial bug-generation AG-UI event order, including streaming text,
  `generate_a2ui`, nested `render_a2ui`, state snapshots, and the A2UI
  `createSurface/updateComponents/updateDataModel` activity;
- every Stage 4 journey run with action-only, update, stale, submit, and
  double-submit outcomes;
- A2UI operation summaries, surface IDs, component types/counts, bindings, and
  action names;
- no prompts, model text, tool arguments/results, user field values, action
  context values, or API keys. Text/tool payloads are reduced to lengths,
  state to public fields, and messages to role counts.

Consecutive identical `STATE_SNAPSHOT` events are displayed as a row range with
a repeat count. This is a display compression only; events are not reordered or
invented. `npm run check:trace` reproduces the required-section and known
secret/user-value scan against the generated file.

## Handoff

`README.md` documents prerequisites, fixture and live environment setup, the
three startup commands, every test command, the fixture-vs-live distinction,
troubleshooting, and a 2–3 minute walkthrough. `docs/protocol-trace.md` lets a
new developer independently compare AG-UI ordering with A2UI operations.

## Residual limits

- Live generation remains probabilistic; a rejected model form is surfaced as a
  retryable UI error and is not replaced by a fixture.
- The demo remains localhost-only with no authentication, production storage,
  external submission, or real-time collaboration.
- The fixture browser suite covers the main keyboard path and mobile width, not
  a full screen-reader or automated axe audit.
- The production bundle warning remains from the installed renderer dependency.

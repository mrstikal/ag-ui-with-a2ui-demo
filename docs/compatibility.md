## Decisions verified against installed declarations

- The CopilotKit v2 provider takes `agentId`, not `agent`.
- `useSingleEndpoint={true}` is required on the provider because the bridge
  uses `mode: "single-route"`. Without it the client calls
  `GET /api/copilotkit/info` and receives 404.
- `CopilotRuntime` accepts `a2ui.schema`, `a2ui.defaultCatalogId`, and
  `a2ui.injectA2UITool`.
- `a2uiCatalogAvailable` makes the runtime inject `render_a2ui` by default.
  The bridge sets `injectA2UITool: false`; the live planner binds only
  `generate_a2ui` from `getA2UITools`.
- `getA2UITools` is imported from `@ag-ui/langgraph`; the catalog validator
  comes from `@ag-ui/a2ui-toolkit`.
- The integrated chat auto-mounts the A2UI renderer when the runtime reports
  `a2ui` in its info response. There is no second renderer.

## Catalog contract

- Catalog ID: `arb://catalog/request-builder.v1`.
- Approved components: `Text`, `Column`, `Card`, `TextField`, `ChoicePicker`,
  `Button`.
- The server schema lives in `packages/shared/src/catalog-schema.json` and is
  generated by `scripts/generate-catalog-schema.mjs` from the installed
  renderer (`createCatalog` + `filterCatalog` + `extractCatalogComponentSchemas`).
- The browser builds the same restricted catalog in `apps/web/src/catalog.ts`
  and compares its extracted schema with the shared JSON. A mismatch throws at
  module load.
- The renderer enforces its catalog ID on `createSurface`. The server
  middleware overwrites the client schema context with its own restricted
  schema. A component outside the approved set is rejected by the toolkit
  validator in `apps/agent/src/fixture.test.ts`, and the browser catalog has
  no implementation for it (`apps/web/src/catalog.test.ts`).

## Vertical slice (historical Stage 0; superseded by Stage 2)

Stage 2 replaced the one-field Stage 0 surface with four fixed bug/feature/
meeting/generic fixtures while preserving the compatibility chain. The current
tool is `publish_fixture_operations`; `build_stage0_fixture` no longer exists.
See `docs/stage-2.md` for the current fixture pipeline.

Processes:

- `apps/agent` — LangGraph dev server, port 2024, graph `requestBuilder`.
  Exports a compiled `StateGraph` with a `messages` channel and no
  checkpointer. The dev server supplies the checkpointer.
- `apps/server` — Express bridge, port 4000, CopilotKit v2 single-route
  endpoint at `/api/copilotkit`, health at `/api/health`.
- `apps/web` — Vite + React 19 + Tailwind 4, port 5173, proxy `/api` to 4000.

Fixture path:

1. A user prompt appends a human message.
2. The graph's `plan` node emits a deterministic `publish_fixture_operations`
   tool call (originally `build_stage0_fixture`). The tool returns a validated
   `a2ui_operations` envelope built with `createSurface`, `updateComponents`,
   and `updateDataModel` from `@ag-ui/a2ui-toolkit`; Stage 2 adds the four fixed
   fixtures and same-surface review updates.
3. The A2UI middleware converts the tool result to `ACTIVITY_SNAPSHOT`;
   CopilotKit renders the surface with native `TextField` and `Button`.
4. The click resolves every bound field plus `revision` from the data model and
   forwards `forwardedProps.a2uiAction.userAction`.
5. The middleware injects a synthetic `log_a2ui_event` tool call/result; the
   graph validates the resolved values, advances `status=review`,
   `revision=1`, and (in Stage 2) emits the same-surface update operations.
6. Channel changes produce `STATE_SNAPSHOT` events.

Fixture text uses `manually_emit_message` plus a persisted `AIMessage` with
`response_metadata.finish_reason`. The manual event streams the text; the
persisted message survives `MESSAGES_SNAPSHOT`. A static `AIMessage` alone is
not enough: the adapter starts a text message but cannot close it without a
finish reason, which produces `RUN_FINISHED while text messages are still
active`.

## Compatibility traps for later stages

- The action request must include the full client message snapshot
  (`MESSAGES_SNAPSHOT.messages`) and state. Sending only the latest user
  message triggers the LangGraph adapter's regenerate path because the
  checkpoint has more messages than the request.
- An action run re-emits `ACTIVITY_SNAPSHOT` only when its tool result contains
  A2UI operations. Stage 0's review emitted none, so the client retained the
  initial activity; Stage 2 emits updates and the bridge rewrites every surface
  snapshot to the stable `a2ui-surface-${surfaceId}` message ID. Do not claim
  an action activity when no operations were emitted.
- Stage 2's valid review writes path-scoped `/meta/revision`, so the rendered
  surface can be reviewed again; invalid review keeps the revision unchanged.
  Stage 4 still owns checkpoint-anchored authoritative revision.
- The fixture action validates against the thread-derived surface ID, requires
  a non-empty title, and rejects a stale `revision` before incrementing. The
  remaining trust issue is that `state.revision` is still a client-mergeable
  channel; Stage 4 must anchor the authoritative revision in the checkpoint
  rather than the merged input state.
- The UI banner prefers the graph's `STATE_SNAPSHOT.mode` over the bridge
  health mode and renders a loud `MODE MISMATCH` state if the two disagree.
  The diagnostics panel also displays `status`, `revision`, and `mode` from
  the `useAgent` state hook.
- The runtime's A2UI middleware receives `toMiddlewareCatalog(...)`, an
  unwrapped component schema with top-level `properties`/`required`. This
  matters once the catalog grows to components that use `componentRef` fields
  beyond the hardcoded `child`/`children` checks.
- The installed `ChoicePicker` renderer stores its value as an array, even for
  `mutuallyExclusive`. Fixture and live validation normalize a one-item array and
  force the plan's single-select contract; the renderer still stores an array.
- Fixture text has one content chunk per message. Stage 3's live run proved
  real model streaming through AG-UI text start/content/end events.
- The live graph binds its single tool with `parallel_tool_calls: false` and
  logs per-turn latency plus token usage when the provider supplies it.
- Stage 0's live graph used the toolkit sentinel surface ID. Stage 3 replaces
  it with a private draft surface, a trusted thread surface, and host-side
  path/action validation.
- `AGENT_MODE` is required and has no silent fallback in both processes.
  The bridge's `/api/health` still reports its own `AGENT_MODE`; the UI
  cross-checks it against the graph state and shows a mismatch instead of
  trusting either side alone.
- The bridge disables CORS (`cors: false`); the browser is same-origin through
  the Vite proxy. POST requests without `Content-Length` are rejected with 411,
  and declared lengths above 64 KiB are rejected with 413. Node's HTTP parser
  enforces the declared length. A future raw-body counter can remove the
  remaining trust in the header.
- The telemetry notice from CopilotKit can be disabled with
  `COPILOTKIT_TELEMETRY_DISABLED=true` if desired.

## Review hardening

The independent review found no blockers or high-severity issues. The
following medium/low findings were fixed:

- banner derives from graph state and detects bridge/graph mode drift;
- fixture action checks the thread-derived surface, non-empty title, and stale
  revision; unparseable `log_a2ui_event` payloads now produce a rejection;
- `respond` no longer claims success when the fixture tool returned an error;
- middleware uses the unwrapped catalog schema;
- CORS disabled; POST without `Content-Length` rejected; 64 KiB cap enforced;
- e2e harness has a 120 s fetch timeout and SIGKILL escalation;
- live graph disables parallel tool calls and logs latency/token usage;
- diagnostics display state read through the `useAgent` hook;
- catalog regeneration is a root npm script and is documented.

The remaining Medium item is intentionally deferred to Stage 4: authoritative
revision must come from the LangGraph checkpoint, not the client-mergeable
`state.revision` channel.

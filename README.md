# Adaptive Request Builder

Adaptive Request Builder demonstrates **an AI agent that creates and updates
an interactive form, not just a text response**. Describe a bug, feature request,
meeting, or custom request in chat; in live mode, the agent composes a form for
that task. You can edit it, ask for changes in natural language, review the
result, and simulate submission. No ticket, email, or calendar event is created.

The demo combines **AG-UI 1.0** for agent-to-application communication with
**A2UI v0.9** for declarative UI descriptions. It shows how model-driven form
composition can coexist with host-owned validation and workflow rules:

1. **Describe the request.** A LangGraph planner calls `generate_a2ui` to
   compose a form from an approved component catalog.
2. **Validate and render it.** The host validates the component tree, bindings,
   and actions before the CopilotKit A2UI renderer displays the form. The model
   does not supply executable JSX, HTML, or CSS.
3. **Edit and review.** Fields update the form's A2UI data model. Clicking
   **Review request** sends the resolved field values and revision back through
   AG-UI; deterministic host logic validates them and updates the same form.
4. **Refine the form.** In live mode, a follow-up such as "add a short
   justification" produces a bounded `apply_request_changes` plan. The host
   applies it to the same form, preserves unrelated saved values, and requires
   another review. Review before sending a follow-up to save browser edits to
   the agent's state.
5. **Simulate submission.** The host accepts only the reviewed revision with
   unchanged values, then displays `Demo only - nothing was sent.` Review and
   submit do not call the model.

A built-in inspector makes the separation visible: AG-UI events describe runs,
streamed text, tools, and public agent state; A2UI operations describe form
creation, field data, updates, and removal. Its diagnostic payloads are bounded
and redacted rather than raw message or field dumps.

The default **fixture mode** demonstrates rendering, review, and removal with
fixed forms and no model credentials. **Live mode** adds real model composition,
streamed responses, follow-up changes, and the full review/submit workflow.

> This is a localhost demo, not a production service. Thread IDs isolate
> drafts but are not access control. Keep the app bound to localhost.

## Technologies and benefits

| Technology | Role in this demo | Benefit |
| --- | --- | --- |
| **AG-UI 1.0** | Carries agent runs, streamed text, tool calls/results, activities, and public state between the agent and UI. | A common event protocol lets the chat, status indicators, and inspector observe the same run without a separate custom transport. |
| **A2UI v0.9** | Describes the form as catalog components, data bindings, and surface operations. | Forms can be composed and updated as data, without hand-written JSX for each request category or executable model-generated UI code. |
| **LangGraph JS** | Orchestrates the planner, tools, deterministic actions, and per-thread checkpoint state. | Separates probabilistic model decisions from authoritative review, revision, and submit transitions. |
| **LangChain / `@langchain/openai`** | Connects the planner and A2UI generation tools to a tool-capable OpenAI-compatible endpoint. | Keeps model configuration separate from the form workflow; the verified provider is OpenRouter. |
| **CopilotKit v2 APIs** | Provide the React chat integration, runtime bridge, and A2UI middleware. | Connect chat, agent events, and form actions through the existing integration instead of a parallel submission API. |
| **CopilotKit A2UI renderer** | Renders the shared, restricted component catalog in the browser. | Reuses trusted field and button implementations while allowing the agent to choose the form's structure. |
| **React 19** | Implements the chat workspace, lifecycle controls, and protocol inspectors. | Combines ordinary application UI with the dynamically described form in one interface. |
| **Tailwind CSS 4** | Styles the trusted local UI and its responsive layout. | Keeps presentation under application control rather than accepting styles generated by the model. |
| **Express 5** | Hosts `/api/copilotkit` and `/api/health` on localhost, with a 64 KiB request-body cap. | Keeps the runtime bridge small and gives the UI an explicit health and mode check. |
| **TypeScript, Zod, and shared validators** | Define types, graph input/output schemas, and strict component, operation, and action validation. | Catch contract errors at build time and reject invalid or unapproved data at runtime; private checkpoint state is excluded from public AG-UI state. |
| **Vite 8** | Serves and builds the web app, proxying `/api` to the local bridge during development. | Provides fast frontend iteration and a same-origin browser-to-bridge path without enabling CORS. |
| **Node.js and npm workspaces** | Run the local services and manage `apps/*` plus `packages/*` as one repository. | One dependency installation and shared scripts cover the agent, bridge, frontend, and common contracts. |
| **Vitest and Playwright** | Cover validation and workflow logic, transport integration, and browser journeys. | Fixture tests provide repeatable regression checks; opt-in live suites verify actual model and end-to-end behavior. |

Exact dependency pins and integration caveats are recorded in
[the compatibility record](docs/compatibility.md) and the workspace manifests.

## Architecture

Three local processes:

1. `apps/agent`: LangGraph dev server on `127.0.0.1:2024`, graph
   `requestBuilder`. It owns the model, catalog rules, private request state,
   review/submit transitions, and bounded follow-up changes.
2. `apps/server`: Express CopilotKit runtime on `127.0.0.1:4000`. It bridges
   the browser to LangGraph, registers the A2UI middleware, and enforces a
   64 KiB request-body cap.
3. `apps/web`: Vite/React UI on `127.0.0.1:5173`. It renders the A2UI form
   through the installed renderer and includes a redacted AG-UI/A2UI inspector.

```text
Browser: React + CopilotKit chat + A2UI renderer
  <-> Vite /api proxy
  <-> Express /api/copilotkit: CopilotKit runtime + A2UI middleware
  <-> LangGraph requestBuilder: planner, tools, private state, action validation
  <-> OpenAI-compatible model endpoint (live generation and follow-ups only)
```

`packages/shared` is not a separate process. It holds the catalog ID
`arb://catalog/request-builder.v1`, generated catalog schema, action parser,
limits, and operation validators used across the workspaces. The approved
components are `Text`, `Column`, `Card`, `TextField`, `ChoicePicker`, and `Button`.

Public agent state contains only `status`, `revision`, `surfaceId`, `category`,
`summary`, and `mode`. Components, field rules, saved values, and the review
snapshot stay in the agent's private checkpoint state. Browser field edits
belong to the A2UI data model until a form action sends their resolved values
back to the agent; they are not synchronized through public AG-UI state.

## Fixture vs live

| | Fixture | Live |
| --- | --- | --- |
| Model request | No | Yes, tool-capable planner |
| Surface source | Four fixed validated definitions: bug, feature, meeting, generic | `generate_a2ui` result, host-validated |
| Deterministic | Yes | No; retry if model output is rejected |
| Credentials | None | `MODEL_ID` and `MODEL_API_KEY` |
| Review / submit | Review and discard; no submit | Deterministic review and simulated submit |
| Follow-up changes | No model follow-up | Bounded `apply_request_changes` plan |
| Evidence | Protocol/UI regression only | Real composition, streaming, and follow-up acceptance |

Both modes share the catalog, strict operation validation, host-owned review
logic, and the same React renderer. Fixture mode is not a silent fallback for a
live-model failure.

## Prerequisites

- Node.js `>=22.12` (verified with Node 22.22.2 and npm 10.9.7)
- A Chromium browser for the optional Playwright suites:
  `npx playwright install chromium`
- For live mode only: a tool-capable OpenAI-compatible model endpoint. The
  verified setup is OpenRouter `deepseek/deepseek-v4.1-flash-1017` with
  `MODEL_BASE_URL=https://openrouter.ai/api/v1` and `MODEL_MAX_TOKENS=4096`.

## Setup

```bash
npm install
cp apps/agent/.env.example apps/agent/.env
cp apps/server/.env.example apps/server/.env
```

Both files default to deterministic fixture mode. Keep `AGENT_MODE` identical
in the agent and server files; the server reports the mode used by the UI
banner, and the UI checks it against the agent's reported mode.

### Live mode

Edit the two local `.env` files (never commit them):

```dotenv
# apps/agent/.env
AGENT_MODE=live
MODEL_ID=deepseek/deepseek-v4.1-flash-1017
MODEL_BASE_URL=https://openrouter.ai/api/v1
MODEL_API_KEY=sk-or-...
MODEL_MAX_TOKENS=4096
```

```dotenv
# apps/server/.env
AGENT_MODE=live
```

Restart both processes after changing their mode or configuration. The model
API key belongs only in the agent configuration, never in the web app or
browser. Live requests send prompts and relevant form context to the configured
provider and may incur API charges; use non-sensitive demo data.

No LangSmith API key is required. The local agent starts with `--no-browser`
and does not open LangSmith Studio.

## Run the demo

Open three terminals in the repository root:

```bash
npm run dev:agent
```

```bash
npm run dev:server
```

```bash
npm run dev:web
```

Open <http://127.0.0.1:5173>. If a port is occupied, stop the old process
before starting another; the bridge and agent cannot switch modes in place.

### 2-3 minute fixture walkthrough

1. Click **Login bug**. A catalog-rendered form appears; the mode badge says
   `FIXTURE` and the composer text says no model was called.
2. Edit **Bug summary** and **Steps to reproduce**, choose a severity, and
   press **Review request**. The same surface shows `Reviewed at revision 1.`
   The inspector shows the forwarded action context and the same-surface A2UI
   update.
3. Optionally click **New request** to clear the surface and start a fresh
   thread. **Discard demo form** is also available in fixture mode for a
   protocol-only cleanup check.
4. Inspect **AG-UI vs A2UI state**: public `STATE_SNAPSHOT` fields are in the
   State filter; `createSurface`, `updateComponents`, and `updateDataModel`
   operations are in the A2UI filter.

### Live action/update walkthrough

1. With live mode configured, click **Login bug** and wait for the streamed
   explanation and generated form.
2. Fill the fields, click **Review request**, and wait for the review
   confirmation.
3. Send a follow-up such as
   `Make this a high-priority request and add a short justification. Keep the existing fields.`
   The model calls `apply_request_changes`; the host validates and applies the
   plan to the same surface at the next revision.
4. Review again and click **Submit demo request**. The UI displays
   `Demo only - nothing was sent.` and removes the action.
5. Use **New request** to start a clean thread.

## Scripts

| Command | Purpose |
| --- | --- |
| `npm run typecheck` | Type-check all workspaces. |
| `npm test` | Vitest unit/integration suites in all workspaces. |
| `npm run build` | Production build of the web app. |
| `npm run test:e2e:fixtures` | Deterministic AG-UI/A2UI transport e2e; starts agent and bridge if absent. |
| `npm run test:e2e:browser` | Deterministic Playwright fixture UI suite; starts all three services. Stop dev servers first. |
| `npm run test:e2e:live` | Opt-in live protocol gate; requires model credentials. This is the mandatory live acceptance run. |
| `npm run test:e2e:browser:live` | Opt-in live Playwright journey; loads `apps/agent/.env` and requires credentials. Starts all three services; stop dev servers first. |
| `npm run check:trace` | Verify the sanitized protocol trace contains the required sections and no known secrets/user values. |
| `npm run generate:catalog-schema` | Regenerate the shared catalog schema from the installed renderer. |

The deterministic commands must run without any model API key. Live commands
exit with status 2 when credentials are missing. Live output is probabilistic;
a rejected initial form is a model-side failure that the UI exposes through
Retry, not a fixture fallback.

The live protocol gate reads credentials from the shell environment; unlike the
live browser wrapper, it does not load `apps/agent/.env` itself. To run it with
the configured credentials:

```bash
set -a; . apps/agent/.env; set +a
npm run test:e2e:live
```

Protocol suites start the agent and bridge if absent; stop any processes in the
opposite mode first. Both browser suites require ports `2024`, `4000`, and
`5173` to be free and start their own services.

To regenerate the sanitized trace from a real live protocol run:

```bash
set -a; . apps/agent/.env; set +a
PROTOCOL_TRACE_PATH=docs/protocol-trace.md npm run test:e2e:live
npm run check:trace
```

## Troubleshooting

- **Port already in use**: stop the process on `2024`, `4000`, or `5173`.
  Playwright configs use `reuseExistingServer: false`, so stop manual dev
  servers before either browser suite.
- **Bridge unavailable / `MODE UNKNOWN`**: check `npm run dev:server`, then
  `curl http://127.0.0.1:4000/api/health`. The UI polls every 5 s and offers
  **Reconnect** after two consecutive failures. Recovery of the same bridge
  instance preserves the conversation; a detected bridge restart starts a
  fresh thread once any active run finishes.
- **`MODE MISMATCH`**: set the same `AGENT_MODE` in both `.env` files and restart
  both processes. The health endpoint reports the bridge's own mode, not the
  agent's; the UI detects disagreement when it receives agent state. Protocol
  suites also assert the expected mode.
- **`A2UI generation failed`**: the model output was rejected or the model
  omitted a required field. Use a tool-capable model, allow more output tokens
  (`MODEL_MAX_TOKENS=4096`), and retry. The app does not fall back to fixtures.
- **Live suite blocked**: export `MODEL_ID` and `MODEL_API_KEY`. If they are
  stored in the ignored `apps/agent/.env`, source it before `test:e2e:live` as
  shown above; `test:e2e:browser:live` loads it automatically.
- **Playwright browser missing**: run `npx playwright install chromium`.
- **Follow-up misses field edits**: click **Review request** before asking the
  model to change the form. Typing updates the browser's A2UI data model, not
  the agent's saved field values; the action carries those values back.
- **Thread/surface confusion**: **New request** clears visible messages, agent
  state, and the A2UI surface before starting a new thread. Old thread IDs are
  not reused; this is a UI reset, not deletion of server-side checkpoints.

Known limits: no authentication or multi-user isolation, no persistent
production store, no external submission, and no real-time collaboration.
Model calls are allowed; submission is simulation-only.

The LangGraph development server does persist local thread checkpoints under
`apps/agent/.langgraph_api`. This is development storage, not a production
database or a guarantee that **New request** erases saved data. Inspector
redaction does not remove data from model requests or local checkpoints, and
the public `summary` can contain request text. Do not use sensitive data or
expose the services on a public interface.
